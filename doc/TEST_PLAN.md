## 二、第 1–2 层：全自动化（一条命令）

### 执行

```bash
bash tools/run_tests.sh all      # 全跑（编译 + 465 项 + 从站自检 + 体检）
bash tools/run_tests.sh unit     # 只跑编译 + 单测，最快
bash tools/run_tests.sh build    # 只验证编译
bash tools/run_tests.sh slave    # 只跑从站协议自检
bash tools/run_tests.sh env      # 只做环境体检 + 覆盖率统计
```

换 Qt 套件：`QTDIR=D:/programming/Qt/5.15.2/mingw81_64 bash tools/run_tests.sh unit`

### 脚本做了什么

1. 自动探测并转换 Qt/MinGW 路径（Git-Bash 下 `D:/a` → `/d/a`）；
2. 新建 `build/verify_app`、`build/verify_tests`，**复用 `build/app6/.qmake.stash`**——
   这一步是必须的：本机 MinGW 工具链探测会失败（`QMAKE_CXX.COMPILER_MACROS is not defined`），
   有缓存则 qmake 直接跳过探测；
3. 编译、跑测试、统计退出码、失败时自动抓 `error` 行；
4. 统计源码覆盖率盲区并提示。

> **CI 已覆盖的部分**：`.github/workflows/tests.yml` 在 Ubuntu 上跑
> 单测 + ASan/LeakSanitizer + Valgrind Memcheck 三个作业，泄漏/非法读写即构建失败。
> 但**只测 `tests/` 里的 10 个模块**，GUI 主程序完全没有内存检查。
> → 见第五层建议：补一个 GUI 冒烟 + 主程序 ASan 构建。

## 三、第 3 层：协议与联调（半自动）

### 3.1 内置模拟从站（推荐起点，零硬件）

```bash
# 方式一：程序内菜单 Advanced → Simulator (Modbus Slave) 一键启停（推荐）
# 方式二：命令行
python slave/modbus_tcp_simulator.py --selftest        # 协议自检（9 项）
python slave/modbus_tcp_simulator.py --port 1502       # 起从站
python slave/modbus_tcp_simulator.py --unit 3          # 多从站联调
```

模拟从站数据布局：

| 寄存器 | 内容 | 用途 |
| --- | --- | --- |
| HR 0 | 正弦温度（×10，250 = 25.0 °C） | 实时曲线 / 仪表盘 |
| HR 1 | 随机游走 | 触发报警阈值 |
| HR 2 | 固定 42 | Equal 条件报警 |
| HR 3–99 | 规律变化 | 批量读写 |
| IR 0–99 | 与 HR 联动 | FC04 |
| Coil/Discrete 0–31 | `discrete[0]` 每 5s 翻转 | FC01/02/05/0F |

支持 FC01/02/03/04/05/06/0F/10，越界返回异常码 02，未实现功能码返回 01。

**联调 checklist**：

- [ ] 起从站 → FieldLink 选 TCP `127.0.0.1:1502`、从站地址 1 → 连接成功
- [ ] 手动读 Holding 0 数量 5 → 正弦值在变
- [ ] 勾选 Auto read（1s）→ 主界面表格原地刷新，不卡顿
- [ ] 建轮询任务（addr 0 / 500ms）→ 曲线平滑、历史库记录数与时间吻合
- [ ] 写 addr 2 = 42 → 自动回读 = 42
- [ ] 配报警 `> 阈值` 于 HR 0 → 触发 → 去抖 → 回落清除 → 确认 → 历史可查
- [ ] 批量任务：读 0 → 写 1 → 读 1，三步顺序执行
- [ ] **停掉从站** → 弹窗「是否重连？」→ 选「是」→ 重启从站 → 自动恢复
- [ ] 自己点 Disconnect → **不弹窗**
- [ ] 历史查询：时间区间 / 从站 / 地址组合 + 最近 N 条 + CSV 导出 + 过期清理

### 3.2 MQTT 联调

python slave/mqtt_test_broker.py --port 1883            # 无认证

### 3.3 独立实现交叉验证（最严格的正确性验证）

用**第三方从站**（ModbusTools 0.5.0）验证 FieldLink 主站，避免"自己实现自己验"。

完整用例表见 **`doc/MODBUS_CROSS_VALIDATION.md`**（41 条，A–J 组）：

| 组 | 内容 | 条数 |
| --- | --- | --- |
| A–D | FC03/04/01/02 四张寄存器表读取 | 9 |
| E | 写闭环 FC05/06/0F/10 + 写后回读 | 6 |
| F | **32 位/浮点字节序与工程换算（重点）** | 10 |
| G | 超量程/零数量/超长分段/异常码 | 6 |

| I | 轮询 / 批量 / 慢响应在途保护 | 3 |

## 四、第 2 层补齐建议（🔴 优先）

三个零覆盖的新模块，建议按此优先级补测试。都是纯逻辑，**不依赖 GUI，写起来很快**：

### 4.1 `PointModel` CSV/JSON 导入导出（最高优先级）

这块最容易出静默 bug（用户数据丢失）。建议用例：

| # | 用例 | 期望 |
| --- | --- | --- |
| 1 | 导出 JSON → 再导入 → 点位数/字段完全一致 | 往返无损 |
| 2 | 导出 CSV → 再导入 → 一致（含 BOM 处理） | 往返无损 |
| 3 | CSV 表头**列顺序打乱** | 仍能定位列正确导入 |
| 4 | CSV 字段**含逗号/引号/换行** | 转义/反转义正确 |
| 5 | 表头**缺列** | 明确失败，不静默错位 |
| 6 | 导入**追加**模式 | 原有点位不丢 |
| 7 | 导入**覆盖**模式 | 旧点位被替换 |
| 8 | **导入中途失败**（第 5 行非法） | 现有点位**不被破坏**（原子性） |
| 9 | `registerType` 传 "3"/"holding"/"保持寄存器" | 三种写法都识别 |
| 10 | `archiveEnabled` 传 "1"/"true"/"是" | 都识别为真 |
| 11 | 空文件 / 只有表头 | 不崩溃 |
| 12 | 导入 1000 个点位 | 无性能问题 |

> 用例 8（原子性）和 3（列自适应）是这块最容易翻车的地方，优先写。

两个对话框改为调用该模块，共 **91 项断言**（DG1–DG9）：

| 组 | 断言数 | 覆盖内容 |
| --- | --- | --- |
| DG1 | 24 | PDU 十六进制解析：空格/逗号/分号/冒号/下划线/连字符/`0x` 前缀/大小写/空串/奇数长度/非法字符/空指针参数/失败时清空缓冲 |
| DG2 | 11 | 十六进制显示：补零到两位、大写、空数组、多字节分隔 |
| DG3 | 18 | 异常码 01–0B 中文解析、未定义码（0x00/0x07/0x09/0x0C/0x0D/0xFF）兜底为「未知异常」、已定义码不退化 |
| DG4 | 10 | 读类负载构造（**大端字节序**）、越界截断、数量为 0 兜底、构造→解析往返一致 |
| DG5 | 9 | 功能码合法性（1..0x7F，拒 0x00/0x80/负数），速查表 17 项一致性 |
| DG6 | 14 | 扫描区间：`1..1`/`1..247`/`5..10` 计数、结束<起始、**0=广播不可扫描**、248/300/负数越界、失败时 total=0 |
| DG7 | 11 | 探测功能码 ↔ 寄存器表映射（03/01/04/02）、未知码兜底、映射与选项表一致性 |
| DG8 | 15 | 扫描生成轮询任务：id=40000+unit 稳定可重现、名称、寄存器表透传、数量/地址兜底 |
| DG9 | 5 | 进度文案、负数发现数夹为 0 |

## 八、本轮补测发现并修复的缺陷（2026-10-09）

给 `PointModel` 补 174 项断言时，测出 **3 个真实缺陷**，均已修复并加了回归断言。

### 缺陷 1（严重·数据损坏）：registerType 数字映射与 Qt 枚举错位

**现象**：CSV 导出→导入后，点位的寄存器类型被静默改成另一种。

**根因**：`exportToCsv` 用 `static_cast<int>(RegisterType)` 写出 Qt 真实枚举值
（`Invalid=0, DiscreteInputs=1, Coils=2, InputRegisters=3, HoldingRegisters=4`），
但 `registerTypeFromToken` 按「表格习惯序号」解析（`0=线圈 1=离散 2=输入寄存器 3=保持`）。
两套编码不一致 → 导出的 `Coils(2)` 再导入时被读成 `InputRegisters(3)`，**寄存器类型悄悄变了**。

**修复**（`src/pointmodel.cpp`）：数字形式严格按 Qt 真实枚举解析，
`Invalid(0)` 与越界值一律拒绝（回落 HoldingRegisters）。这与导出路径对称，往返无损。

**影响**：凡是用「导出 CSV → 改点表 → 导入」流程的点位，线圈/离散输入/输入寄存器三类
都会被错位成别的类型，读到完全不同的寄存器。**已修复。**

### 缺陷 2（严重·数据丢失）：导入失败会清空现有点位

**现象**：点表有 20 个点位时，导入一个「只有表头」或「全无效行」的 CSV，
点表被清空，只弹一个错误提示。

**根因**：`importFromCsv` 在**解析之前**就 `m_points.clear(); m_values.clear();`（覆盖模式），
解析完才发现一条有效点位都没有 → 返回 false，但数据已被清空。
`importFromJson` 同样问题；`importAuto` 更隐蔽 —— 它为「探测格式」就先跑一次
`importFromJson(append=false)`，仅仅探测失败就会清空数据。

**修复**（`src/pointmodel.cpp`）：三个导入函数全部改为**先解析到临时 `QVector`，
确认至少有一条有效点位后才改动现有数据**；`importAuto` 在覆盖模式下
改为「在临时 `PointModel` 上探测格式 → 确定后再对自身执行真正导入」。

**影响**：这是我在测试方案里列为「最高优先级」的用例 8，**已确认存在并修复。**

### 缺陷 3（轻微·语义不一致）：空行 CSV 与无效行 CSV 返回值相反

**现象**：`,,,\n,,\n`（全空单元格）返回 `true`，而「有内容但 name/address 全空」
返回 `false`。两者都是「什么也没导入」，却一个成功一个失败。

**修复**：明确区分两种语义 ——
- **完全无内容**（空文件 / 只有空白与空单元格）→ 返回 `true`，`imported=0`（不是错误）
- **有内容但无一条有效点位** → 返回 `false` 并给出「请检查表头或列顺序」提示

### 已知遗留问题（不影响正常使用）

`RegisterType::Invalid`（枚举值 0）**无法往返**：导出写 0，导入把 0 当非法值拒绝并回落
HoldingRegisters。正常流程不会创建 Invalid 点位（UI 只能选四张表），仅手工编辑的 CSV
可能出现。已用 `CHECK_ISSUE` 记录为已知问题（测试套件显示「已确认已知问题: 1」）。
